# Write a warm intro

Use before `send_intro_message`. That tool pauses for the user's approval, so what
you draft is what they will be asked to sign their name to — write it as if they
wrote it.

## What makes an intro get answered

1. **A specific reason, in the first sentence.** "I saw you're building <thing>"
   beats "I'd love to connect." Pull the specific from their profile, a post, or a
   podcast episode you actually retrieved — never from a guess.
2. **The overlap, stated plainly.** One sentence on what the sender is building and
   where the two genuinely touch. If you cannot find a real overlap, say so to the
   user rather than manufacturing one.
3. **One small ask.** A 15-minute call, a question they can answer in a line. Not
   "let's chat sometime" and not a request for work.
4. **Short.** Four sentences. An intro that needs scrolling doesn't get a reply.

## Voice

Write in the sender's voice, not yours. No "I hope this finds you well", no
"synergies", no exclamation marks stacked on enthusiasm. Warm and direct, the way
someone would actually message a peer.

## Before you send

Show the user the draft and name the recipient and the reason. When the approval
prompt comes back, do not describe the message as sent until you have the tool's
success result.
